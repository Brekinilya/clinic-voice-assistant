# Голосовой ассистент регистратуры

Принимает звонки пациентов поликлиники, записывает на приём, переносит и отменяет записи, напоминает о визитах. Медицинские, конфликтные и нестандартные обращения передаёт регистратору вместе с карточкой разговора.

Кейс DBI, продуктовый хакатон «Точка сборки», 13–31 октября 2026.

## Статус

Реализованы текстовый диалог, браузерный голосовой канал, SIP/ARI, правила NLU и safety,
импорт расписания Excel, запись, перенос и отмена после подтверждения, журналы PostgreSQL.
Текст и голос используют один диалоговый сервис. Это прототип: исходящие напоминания,
полноценная карточка оператора, callback, `/escalations` и часть FAQ требуют завершения.
T05 ограничивает общий бюджет МИС и ожидание, T06 восстанавливает неизвестные
операции чтением без повторного создания. Приёмка всего кейса ещё не завершена.

### Общие справки T09

В текстовом и голосовом диалоге доступны часы поликлиники, операторов, забора
крови и выдачи результатов; адрес, документы на приём, порядок прикрепления,
общие сроки анализов и способы получения результатов. Источник фактов и правил
распознавания — `config/information.yaml`, РГ-ТЕЛ-01, версия 1.0 от 25.09.2026.
Ответ API содержит `information`: тему, документ, версию и пункты источника.

Примеры: «До скольки вы работаете?», «Как прикрепиться?», «Сколько делают анализ
крови?» → уточнение типа → «Биохимический». ФИО и запросы МИС для этих справок
не нужны. Вопрос посреди оформления сохраняет параметры и повторяет текущий
вопрос; сама справка не подтверждает запись и не продлевает бронь.
Праздничный график и личную готовность анализов помощник не выдумывает.
Значения анализов не сообщает и не оценивает, предлагает обратиться к врачу.
График конкретного врача и вызов на дом этим блоком не завершены.

Проверенная основа T03 — `13bd7c7`: локально **1724 passed, 63 skipped**,
включая 56 пропущенных полных сценарных тестов. Это проверка с PostgreSQL,
а не доказательство работы выданной ВМ, внешней МИС или всех телефонных сценариев.
Результаты новых версий нужно подтверждать отдельно.

## Процессы и состояние

В рабочем режиме (`APP_MODE=hackathon`, `DIALOGUE_ENABLED=true`) настройки не дают запуститься без
`DIALOGUE_MODE=natural`, `DIALOGUE_STORAGE=postgres` и индекса расписания. Всё, что должно пережить
перезапуск, лежит в PostgreSQL. Хранилища в памяти (`Memory*Store`) работают только в демо
`offline_test` и в тестах.

| Процесс | Запуск | Что делает | Почему отдельно |
|---|---|---|---|
| `app` | `deploy/vm/compose.yaml` | HTTP API, текстовый диалог, панель, API оператора | Принимает обращения; телефонию не трогает (`TELEPHONY_ENABLED=false`) |
| `recovery` | `python -m app.recovery watch` | Сверяет чтением операции МИС с неизвестным исходом: запись, отмена, перенос | Не отправляет изменений: повтор вслепую невозможен, неясное уходит в ручную проверку |
| `schedule-updater` | `python -m app.scheduling.cli refresh-loop` | Пересобирает SQLite-индекс расписания из Excel и справочника до истечения срока | Долгая работа не задерживает разговор; один писатель — файл блокировки |
| `voice` | `deploy/voice/compose.yaml` | Голос: WebSocket, ARI и RTP Asterisk, VAD/ASR/TTS. Исполнитель исходящих напоминаний T11 — раз в 15 с | Исполнителю нужен тот же канал ARI, что и звонкам, поэтому он внутри голосового процесса. Входящий разговор он не прерывает |
| `database` | PostgreSQL 17 | Общая база всех процессов | — |

**Что в PostgreSQL** (переживает перезапуск любого процесса):
- состояние диалога и квитанции ходов;
- удержания и журнал операций записи, отмены и переноса;
- заявки и попытки перевода T08, задачи обратного звонка;
- задания и попытки обзвона, контакты, отказы;
- общий бюджет запросов к стенду (`PostgresBudget`: окно лимита `MIS_RATE_LIMIT_PER_MIN` и пауза после 429 общие для всех процессов команды).

Ровно один исполнитель гарантируется арендой (lease) с ограничением по времени и уникальностью попытки в базе, а не памятью процесса.

**Что намеренно только в памяти процесса** и что будет при его перезапуске:

| Состояние | Где | После перезапуска |
|---|---|---|
| Звук, таймеры и очередь реплик звонка | `CallSession`, `SpeechRuntime` | Звонок обрывается. Состояние диалога в базе; неотвеченная попытка T11 становится `unknown` → `manual`, без повторного звонка |
| Карта каналов ARI и портов RTP | `Telephony` | Строится заново при подключении к ARI |
| Кэш чтения справочника и продолжение постраничного чтения | `HttpMedicalSystem` | Читается заново с ограниченной свежестью (`FRESHNESS_S`) |
| Загруженные модели | `Engines` | Загружаются и прогреваются до первого звонка |

Звук разговора не сохраняется нигде. Квитанции ходов в базе нужны для идемпотентного повтора, а в журналы процессов попадают только коды событий, номера звонков и задержки, без реплик.

## Запуск

### Текстовый демонстрационный режим

Нужны Python 3.11+ и Docker Compose. Из корня проекта весь локальный offline-стенд
поднимается одной командой на Windows, Linux или macOS:

```bash
python scripts/demo_up.py
```

Команда создаёт `.env` только если его ещё нет, проверяет, что существующая конфигурация
остаётся в `offline_test`, применяет миграцию PostgreSQL, собирает и запускает приложение и
дожидается `/health/ready`. Она не обращается к внешней МИС и не включает телефонию.
Откройте `http://127.0.0.1:8000/chat`; пароль команды хранится в `.env` и не печатается.
Чтобы остановить контейнеры, выполните `docker compose down` из корня репозитория.

Ручной пошаговый запуск (например, для диагностики):

```bash
uv sync --locked
uv run --no-sync python deploy/vm/configure_env.py --mode offline_test
mkdir -p data
docker compose --env-file .env -f deploy/vm/compose.yaml build app
docker compose --env-file .env -f deploy/vm/compose.yaml up -d database
docker compose --env-file .env -f deploy/vm/compose.yaml run --rm app python -m app.backend migrate
docker compose --env-file .env -f deploy/vm/compose.yaml up -d app
```

Скрипт создаёт `.env` с новыми паролем базы и постоянным ключом диалога;
существующий файл не перезаписывает. Не удаляйте рабочий `.env` для повторного запуска:
иначе будут потеряны постоянные реквизиты базы и диалога. Пароли не выводятся.
Локальный `compose.yaml` сохраняет привязку к localhost; отдельный `deploy/vm/compose.yaml`
публикует порт 8000 для прокси платформы, не открывая порт PostgreSQL.

Чат — `http://127.0.0.1:8000/chat` или публичный HTTPS-адрес выданной ВМ.
Профиль ВМ требует вход: логин `clinic`, случайный пароль находится в `.env`
в поле `WEB_ACCESS_PASSWORD`. Это отдельный пароль демонстрации, не токен МИС.
Браузер покажет стандартное окно входа. Секрет не передаётся через URL или JavaScript.
HTTP API, документация и WebSocket закрыты тем же входом; чтение `/health/live`
и `/health/ready` остаётся публичным. Используйте внешний адрес только по HTTPS.
Общий вход команды не является идентификацией пациента или клинической системой ролей.
Учебный пациент — **Иванов Иван Иванович, 01.01.1990**.
Начните с «Хочу записаться к терапевту», затем ФИО с датой рождения, выбор времени и «Да».
Страница явно обозначает эмулятор с вымышленным расписанием.
Пациенты, записи и диалоги эмулятора находятся в памяти: перезапуск сбрасывает их вместе.
После перезапуска начинайте новый диалог. PostgreSQL в этом режиме проверяется через
readiness; долговечные операции и диалоги обязательны при подключении внешней МИС.

Без Docker установите PostgreSQL, настройте `.env.example`, включите
`BACKEND_DEMO_ENABLED=true`, `DIALOGUE_MODE=natural`, `DIALOGUE_STORAGE=memory`, задайте
постоянный `DIALOGUE_HASH_KEY` от 32 байт, затем:

```bash
uv run --no-sync python -m app.backend migrate
uv run --no-sync uvicorn app.main:create_app --factory --host 0.0.0.0 --port 8000
```

`/health/live` проверяет процесс, `/health/ready` — PostgreSQL.
Они не подтверждают доступность МИС, качество ASR или прохождение сценариев.

### Тестовый стенд организаторов и Excel

Платформа задаёт `DBI_API_TOKEN` и `DBI_API_URL`, приложение использует
`MIS_TOKEN` и `MIS_BASE_URL`. `configure_env.py --mode hackathon` сопоставляет их
и приводит адрес стенда к `/api/v1`. Для этого варианта создавайте `.env` **до первого
запуска**, без существующего рабочего файла. Для перехода с уже работающего эмулятора
сохраните пароль базы и постоянный ключ диалога, изменив только режим и параметры МИС.

```bash
uv run --no-sync python deploy/vm/configure_env.py --mode hackathon
mkdir -p data
docker compose --env-file .env -f deploy/vm/compose.yaml build app
docker compose --env-file .env -f deploy/vm/compose.yaml up -d database
docker compose --env-file .env -f deploy/vm/compose.yaml run --rm app python -m app.backend migrate
docker compose --env-file .env -f deploy/vm/compose.yaml run --rm --user "$(id -u):$(id -g)" app \
  python -m app.scheduling.cli fetch-doctors --output data/doctors.json
docker compose --env-file .env -f deploy/vm/compose.yaml run --rm --user "$(id -u):$(id -g)" app \
  python -m app.scheduling.cli import-xlsx data/schedule.xlsx \
  --catalog data/doctors.json --output data/schedule.sqlite
docker compose --env-file .env -f deploy/vm/compose.yaml run --rm app \
  python -m app.scheduling.cli check data/schedule.sqlite
docker compose --env-file .env -f deploy/vm/compose.yaml up -d app
```

Предварительно скопируйте выданную книгу в `data/schedule.xlsx`. ID Excel вроде `D001`
не являются ID МИС: импорт сопоставляет ФИО и профиль. Индекс привязан к режиму,
адресу и токену команды. По умолчанию срок актуальности — 24 часа; контролируемое
обновление выполняется повторным импортом с `--replace` после сверки справочника.
Неподтверждённые участок или направление могут потребовать регистратора:
отсутствие факта допуска не считается разрешением.

Внешний лимит — 10 запросов в минуту на команду, внутренний — 8. Все процессы команды
(разговоры, сверка, импорт каталога, будущие исходящие задания) делят одно окно в
PostgreSQL с приоритетами: запись после согласия и сверка пользуются всем окном,
разговор оставляет им одно место, фоновые задачи — три. Ход разговора ждёт окна
не дольше `MIS_TURN_WAIT_S` (8 с); дольше — честное «подождите около N секунд» с
закреплённым за звонком местом, а после `MIS_WAIT_LIMIT_S` (120 с) ожидания без
движения — регистратор. Пауза после 429 закрывает окно для всех. Понимание реплик
(«да», «оператора», новая дата, safety) не обращается к МИС: имена врачей берутся из
каталога индекса. Подробности и таблица запросов по сценариям — `bench/mis/README.md`.
Схема PostgreSQL — версия 13: после обновления выполните `python -m app.backend migrate`.
В `hackathon` чат работает с настоящим тестовым стендом на вымышленных пациентах;
незаметной подмены эмулятором нет. Не печатайте `.env`, `/opt/hackathon/ai.env`
или `docker compose config` в общий лог: развёрнутая конфигурация содержит секреты.

M-09 в рабочем `hackathon`-процессе использует локальный `config/paid_prices.yaml`.
Текущая запись (УЗИ щитовидной железы — 1300 ₽) перенесена из сценария M-09 тестового
стенда; это не актуальный прайс реальной клиники и не подключение к внешнему каталогу цен.
Перед любым использованием с пациентами значение нужно сверить с официальным прайсом.

Сохранённые заявки листа ожидания доступны сотруднику в защищённой панели `/debug`.
Панель показывает технический ID пациента, специальность, пожелания и исходный звонок;
отдельный процесс обзвона или автоматическая обработка этих заявок не настроены.

### Исходящие напоминания С-10

Диалог, исполнитель и телефония соединены: проверка адресата → единственный визит →
подтверждение прихода, перенос, отмена или отказ от обзвона. Перенос и отмена используют
существующие доменные сервисы, подтверждение и отказ — журнал PATCH комментария клиента.
Неизвестный PATCH только сверяется чтением, после обрыва ответившему пациенту автоматически
не перезваниваем. Для каждого подходящего визита событие `reminder_sms` ставится в outbox
вместе с заданием напоминания. Отказ только от звонков сохраняет SMS-напоминание; полный отказ
от уведомлений блокирует ожидающие отметки уведомлений. В режиме hackathon отдельный worker
добавляет в комментарий карточки MIS одну строку вида `SMS Напоминание #<ID> ДД.ММ.ГГГГ ЧЧ:ММ`.
Это журнал намерения, а не отправка SMS: провайдера SMS в проекте нет, пациент сообщение не
получает. Строка события, идентификатор и GMT+4-время фиксируются до PATCH. Неизвестный исход
сверяется только чтением; длинный комментарий не обрезается и переводит задание в ручную
проверку. CLI очереди показывает только идентификатор события, вид, статус и безопасный код ошибки.

Заявки листа ожидания можно посмотреть локальной командой
`python -m app.waitlist.cli list --limit 50`. Это даёт регистратуре способ прочитать заявку,
но свободные слоты автоматически не подбираются, а пациенту ничего не отправляется.

Для записи отметок нужны PostgreSQL, миграция схемы 14 и профиль `APP_MODE=hackathon`.
Постоянный worker можно запустить для VM compose профилем `outbox`; он использует тот же
общий бюджет MIS и уступает активному разговору. Статусы очереди доступны через
`python -m app.outbox.cli status`, а неизвестный исход проверяется командой
`python -m app.outbox.cli --client-comment reconcile <EVENT_ID>`. Это отдельная интеграция с
реальной MIS, её не включайте до проверки резервной копии и окна выкладки. Сам по себе worker
не отправляет SMS.

Для исходящих голосовых напоминаний нужны PostgreSQL, голосовой процесс с `TELEPHONY_ENABLED=true` и
`REMINDERS_ENABLED=true`. По умолчанию обзвон выключен. Локальный контакт добавляется явно:

```bash
uv run python -m app.backend migrate
uv run python -m app.reminders.cli contact-set --client-id <ID_тестового_пациента>
uv run python -m app.reminders.cli jobs --day 2026-10-20
```

Телефона в МИС нет: контакт берётся из PostgreSQL и ограничен белым списком SIP.
Автоматический отбор работает по календарю `config/calendar.yaml`, за рабочий день до приёма,
в GMT+4, только для визитов старше суток. Сегодняшняя новая запись не подходит для немедленного
показа напоминания. Готовность живого SIP, моделей и конкретных данных проверяется отдельно;
сквозной тест на эмуляторе не заменяет реальный звонок.

### Проверки и ограничения

Все проверки CI одной командой — нужен только Docker, без `.env` и своей PostgreSQL:

```bash
docker compose -f compose.test.yaml run --rm tests
```

Внутри — одноразовая PostgreSQL в памяти, ruff, форматирование и весь pytest, включая голос
(модели не скачиваются). Часть тестов: `-e PYTEST_ARGS="tests/voice"`. Убрать за собой:
`docker compose -f compose.test.yaml down -v`.

То же без Docker:

```bash
uv sync --locked --extra voice
uv run --no-sync ruff check .
uv run --no-sync ruff format --check .
APP_MODE=offline_test TELEPHONY_ENABLED=false uv run --no-sync pytest
```

Для интеграционных тестов нужен `TEST_DATABASE_URL` к отдельной PostgreSQL;
тесты создают и удаляют собственные схемы. Голосовые unit-тесты не скачивают модели.

Локальные RulesNlu извлекают намерения и параметры без LLM; проверка пациента, времени, права на действие
и подтверждение находятся вне модели. Неопределённый ответ на POST требует сверки,
а новая речь отзывает прежнее согласие. Ассистент не ставит диагноз и не назначает лечение.
`clinic_pilot` отключён: допуск к настоящим данным и защищённый контур не подтверждены.

Конфигурация ВМ подготовлена для развёртывания; её успешный запуск на выданной машине
нужно подтвердить отдельно. Браузерный чат позволяет показать сценарий текстом,
если голос требует настройки, с явным указанием режима МИС.
