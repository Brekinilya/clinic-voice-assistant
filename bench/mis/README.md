# Бюджет МИС (T05): запросы и время сценариев

Замер: `python bench/mis/budget_table.py`. Сценарии С-01, С-03, С-04, С-05 идут репликами из
`tests/scenarios/main/*.yaml` через текстовый API, настоящий HTTP-адаптер и эмулятор стенда.
Время виртуальное: реплика пациента вместе с ответом занимает 6 с; ожидание бюджета двигает
те же часы. Бюджет — алгоритм `app.mis.budget`, лимит 8 в минуту: тот же, что у
`PostgresBudget`. Что окно действительно общее для процессов, проверяет
`tests/test_mis_budget_postgres.py`: два звонка, фоновая задача и второй процесс с
отдельным пулом соединений, эмулятор с внешним лимитом 10 — ни одного 429.

**Нагрузка «+ второй звонок и фон»** — одновременно идёт вторая запись С-01 и фоновая задача.
Задача трижды, раз в 20 с, читает справочник врачей и записи на завтра. Все — в том же окне.

**Профиль «85 врачей, >50»**:

- 85 врачей;
- у каждого учебного пациента 60 однофамильцев по дате рождения;
- по 60 чужих записей в день у учебных врачей.

## Выводы

- **Все сценарии дошли до результата.** Ни одного 429. В любые 60 с все участники вместе
  сделали не больше 8 запросов.
- **Запись С-01 в одиночку — 9 запросов.** Один из них — справочник для понимания: у учебного
  расписания нет каталога врачей. В режиме `hackathon` имена берутся из каталога SQLite-индекса,
  и запись укладывается в 8.
- **Перенос С-03 больше окна при любой нагрузке** (18–25 запросов).
  - Это создание новой записи, отмена прежней и свежие проверки перед каждым изменением.
  - Пациент дважды-трижды слышит «подождите около N секунд». Места на это время закреплены
    за звонком, и опередить его другой звонок не может.
- **Больше восьми страниц** (выборка 541 записи на день для С-10) читаются продолжением с
  прерванной страницы: 11 запросов за 2 минуты, а не бесконечные повторы с начала.
  - Фоновое задание уступает разговорам: в любые 60 с оно берёт не больше 5 мест.
- **С-10 как исходящий звонок не реализован (T11).** В таблице — только будущая фоновая
  выборка, через тот же бюджет с фоновым приоритетом.
- **Бронь на 90 с бывает короче обещанного ожидания под нагрузкой.**
  - После долгой паузы диалог предлагает варианты или подтверждение заново и не записывает
    по устаревшей брони.
  - Продлевать бронь на время ожидания — решение для T06.
